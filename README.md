# mcd-groupmeal · 团餐满减优化引擎

> 麦当劳程序员节创意开发大赛参赛作品 · **真实使用麦当劳中国 MCP**：`delivery-query-stores` → `query-meals` → `query-meal-assistance` → `query-promotions` → `calculate-price`
> 纯 ESM JavaScript，**零运行时依赖**，一行命令可跑；**没有 Token 也能用内置演示数据跑通全流程**。

**它不是点餐助手，是算钱工具。** 输出可量化、可复现、可证伪。

> 📖 **不知道怎么开始？看 [`docs/USER-GUIDE.md`](./docs/USER-GUIDE.md)** —— 四种用法（零安装 / Windows 双击 / 命令行 / 当库引入）、完整参数表、输出逐列解读、前置条件与故障排查。
> 📱 **在手机上点餐怎么用最省？看 [`docs/PHONE-GUIDE.md`](./docs/PHONE-GUIDE.md)** —— 到店自取 / 麦乐送、券找货、六个实测坑（打烊 `600057`、券商品不在菜单、券分渠道…）。

```bash
node src/cli.mjs optimize --people 20 --budget 35 --address 西安   # 团餐
node src/cli.mjs phone --city 西安市 --keyword 长安大厦 --want 巨无霸,中杯美式   # 手机点餐
```

**真实运行结果（不是示意图）**：20 人 · 人均预算 ¥35 · 西安某写字楼地址
→ 3 家可配送团餐门店、最优门店实付 **¥504.80**、人均 **¥25.24**、总优惠 **¥209.20（31.2%）**，
拆单结论「**别拆**」（拆 2 单要多付 ¥26.42~52.55）。完整原样输出见 [`docs/EXAMPLE-RUN.md`](./docs/EXAMPLE-RUN.md)。

手机点餐同一天实测：西安长安大厦到店自取「巨无霸 + 中杯美式」
→ 5 家门店里当晚只有 1 家营业，用账号里的「新人专享-中杯美式7折」实付 **¥39.80**（省 ¥5.70），
且该券锁着的「美式中杯」**在 130 项菜单里根本搜不到**（券专属商品）。详见 [`docs/PHONE-GUIDE.md`](./docs/PHONE-GUIDE.md)。

## 为什么值得 star

| | 常见做法 | 本项目 |
|---|---|---|
| 门店范围 | 先定位**一家**店，在这家店里优化 | **同一地址下所有可配送团餐门店横向比价**（实测 8 城合计 22 家可配送团餐门店） |
| 优惠规则 | 只看券 / 只做凑单提示 | 解析官方 `query-promotions` 的**满折阶梯**（实测全品牌统一：满 ¥300→7.8 折、¥500→7.4 折、¥1000→7 折、¥2000→6.6 折） |
| 助餐档位 | 默认用系统选中的那档 | **三档助餐一起比价**（保鲜速达 / 专人分餐 / 专人摆台）。实测同样一餐选错档位，20 人要**多付 ¥100.50** |
| 拆单 | 默认「拆单更省」或干脆不做 | **穷举 k≤3 拆法，逐单用官方 `calculate-price` 验价；不赚就明说别拆** |
| 结论 | 承诺「立省 X 元」 | 每个方案都有官方算价回执，`--json` 可复现整条推理链 |

### 关于「拆单」的诚实结论（本项目的差异点）

我们**不承诺拆单能省钱**，而是把它算清楚：

- **满折**（`ruleCategory=30`，实测当前所有团餐门店都是这一类）：
  拆分只会降低折扣档位（整体命中档位 `R ≥ max(rᵢ)`，故 `Σpᵢ(1−rᵢ) ≥ P(1−R)`），
  而且会重复支付配送费、并失去免配送费资格（实测 **¥510 起免配送费，¥300 仍收 ¥6**）。
  → 实测：20 人单拆 2 单要多付 **¥26.42~52.55**。**结论就是「别拆」。**
- **满减**（`ruleCategory=40`）：才可能出现「拆了真赚」（满 100 减 20 ×2 > 满 200 减 20）。引擎同样支持。

> 我们宁可给出一个「不用拆」的诚实答案，也不给一个会被用户当场算穿的建议。

## 它能回答的三个问题

1. **同一顿饭，附近哪家团餐门店最便宜？** —— 跨门店比价矩阵，全部由官方算价确认。
2. **同一家店，选哪个助餐档位最划算？** —— GMS001/002/003 三档一起算（后两档需提前 ≥4 小时预约）。
3. **要不要拆单？拆几单？** —— 穷举 + 官方验价 + 明确的「别拆」结论。

外加一个官方引擎主动告诉你的增量信息：**再加多少钱能升级到下一档折扣**（`calculate-price` 返回的 `enjoyable.balance`）。

### 还能回答「我在手机上点餐怎么点最省」（`phone` 模式）

团餐之外，`phone` 模式面向**个人手机点餐**（到店自取 / 麦乐送）：
给它「位置 + 想吃什么」，它把**你账号里该店该渠道可用的券** × **门店菜单** × **官方算价**交叉一遍，
输出「去这家店、点这些、勾这张券、实付这么多」。

```bash
node src/cli.mjs phone --city 西安市 --keyword 长安大厦 --want 巨无霸,中杯美式
node src/cli.mjs phone --channel delivery --address 西安 --want 巨无霸,薯条
node src/cli.mjs phone --demo                       # 离线演示，不需要 Token
```

完整的手机点餐用法、六个实测坑与边界说明见 **[`docs/PHONE-GUIDE.md`](docs/PHONE-GUIDE.md)**。

## 快速开始

### 最省事的两条路

- **Windows 不想碰命令行**：双击 `bin\mcd-meal.cmd` —— 依次问你「人数 / 人均预算 / 地址」，出比价结果；失败时直接告诉你下一步该点哪里。
- **手机上点餐**：双击 `bin\mcd-phone.cmd` —— 依次问你「城市 / 位置 / 想吃什么 / 预算」，出「手机点餐卡」。
- **只想先看效果**：双击 `bin\mcd-demo.cmd`（内置演示数据，不联网、不需要 Token）；手机点餐用 `bin\mcd-phone.cmd --demo`。
- **本机自检**：双击 `bin\mcd-doctor.cmd`（Token / 握手 / 工具清单 / 地址簿，一次看清）。

### 0. 零配置试用（不需要 Token，不发任何网络请求）

```bash
node src/cli.mjs demo
```

### 1. 配置 MCP Token

复制 `mcp-config.example.json` 为 `mcp-config.json`，把 `YOUR_MCP_TOKEN` 换成你在 <https://open.mcd.cn/mcp> 控制台申请的 Token：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer YOUR_MCP_TOKEN" }
    }
  }
}
```

> `mcp-config.json` 已在 `.gitignore` 中，**永远不要提交真 Token**（官方《参赛声明》硬性要求）。
> 也支持环境变量：`MCD_MCP_TOKEN` / `MCD_MCP_URL`。

> ⚠️ **硬前提：你的麦当劳账号里必须已有配送地址。**
> `delivery-query-stores` 只接受 `addressId`，而 `addressId` 只能来自账号地址簿。
> **没有地址 = 一家门店都查不到**（这是假阴性，不是工具坏了）。本项目会明确报 `EMPTY_ADDRESS_BOOK` 而不是静默返回 0 家。

### 2. 跑一次真实比价

```bash
node src/cli.mjs doctor                                   # 先自检：握手 / 工具清单 / 地址簿
node src/cli.mjs optimize --people 20 --budget 35 --address 西安
node src/cli.mjs optimize --people 20 --budget 35 --address 西安 --reservation "2026-10-16 12:00"
node src/cli.mjs stores --address 西安                     # 只看门店情报（最省调用量）
node src/cli.mjs optimize --people 20 --budget 35 --address 西安 --json
```

### 3. 复现文档里的实测数据

```bash
node tools/lifeline-probe.mjs   # A~E 生死线验证 → docs/LIFELINE.md
node tools/city-scan.mjs        # 8 城门店/店间价差/折扣阶梯 → docs/CITY-COMPARISON.md
node test/core.test.mjs         # 33 个单元测试（含手机点餐 9 项）
```

## 设计要点

### 官方搭配分档 → 可执行约束

`query-meals` 的官方 Description 为团餐场景给出了人均预算搭配建议，本项目把它实现为 `src/tiers.mjs` 里的约束表：

| 人均预算 | 官方建议搭配 | 约束实现 |
|---|---|---|
| < ¥20 | 小食 | `snack ≥ 1` |
| ¥20–30 | 汉堡 + 小食 或 汉堡 + 饮料 | `burger ≥ 1 && (snack ≥ 1 \|\| drink ≥ 1)` |
| ¥30–40 | 汉堡 + 薯条/小食 + 饮料 | `burger ≥ 1 && drink ≥ 1 && (fries ≥ 1 \|\| snack ≥ 1)` |
| ¥40–50 | 汉堡 + 薯条 + 小食 + 饮料 | `burger + fries + snack + drink 各 ≥ 1` |
| > ¥50 | 丰富组合，优先不重复小食 | 上述 + `distinctSnack ≥ 2` |

### 唯一权威口径

所有对外数字都来自官方 `calculate-price`；本地规则模型（`src/promotions.mjs`）**只用于候选预筛**。
单元测试里用 2026-10-15 的**真实回执**校准了离线定价器（¥30 / ¥300 / ¥510 / ¥1005 四个点全部对上），因此 `demo` 模式与线上行为一致。

### 金额精度

进入业务层前统一转「分」（int）。`calculate-price` 原生返回分，其余工具是元字符串。
全程整数分加总，展示层统一 `¥xx.xx`。

### 调用预算与限流

| 措施 | 实现 |
|---|---|
| 本地缓存 | 门店画像 TTL 10 分钟（`--no-cache` 关闭） |
| 候选预筛 | 本地模型先筛掉明显超预算的篮子，只有入选的才调 `calculate-price` |
| 令牌桶限流 | 客户端内置 600 rpm 令牌桶 + 429 指数退避 |
| 单次运行上限 | `--max-calls`（默认 150）；实测一次 20 人比价约 **98 次算价** |
| 故障降级 | 单店单接口失败（实测遇过 `code=500`）只降级该店，不让整次比价崩掉 |

## 项目结构

```
bin/
  mcd-meal.cmd       双击即用：问人数/预算/地址 → 出比价结果
  mcd-phone.cmd      双击即用（手机点餐）：问城市/位置/想吃什么/预算 → 出点餐卡
  mcd-doctor.cmd     自检：Token / 握手 / 工具清单 / 地址簿
  mcd-demo.cmd       演示模式（无需 Token）
  meal.mjs           上面三个 .cmd 调用的友好入口（中文提示 + 失败指引）
  phone.mjs          手机点餐的友好入口（同上，手机点餐版）
src/
  cli.mjs          CLI 入口（optimize / phone / stores / demo / doctor）
  mcp-client.mjs   零依赖 Streamable HTTP JSON-RPC 客户端（会话、SSE、限流、退避）
  json.mjs         MCP 返回体「markdown + 内嵌 JSON」的平衡花括号解析器
  mcd.mjs          官方工具的领域封装 + 归一化（含业务错误码处置与降级、文字型工具）
  promotions.mjs   满折/满减规则解析 → 可判定谓词 + 折扣函数
  tiers.mjs        官方人均预算分档 → 可执行约束
  basket.mjs       候选篮子生成（满足分档与偏好）
  split.mjs        拆单枚举（k ≤ 3，含「拆了不赚」的数学判据）
  optimizer.mjs    跨门店 × 助餐档 × 篮子 × 拆单 的求解与打分（团餐）
  phone.mjs        手机点餐求解：门店 × 券 × 清单 × 渠道 的实付比价（个人单）
  render.mjs       比价矩阵 / 结论 / 凑单提示的渲染
  mock.mjs         离线演示后端（**演示数据**，代码路径与线上一致）
  money.mjs        分/元换算与格式化
tools/
  lifeline-probe.mjs  A~E 生死线验证器
  city-scan.mjs       多城市门店与店间价差扫描器
test/core.test.mjs    33 个零依赖单元测试
docs/                 使用指南 + 手机点餐指南 + 实测报告（原样输出、生死线、8 城对比）
```

## 目标用户

- **公司行政 / 团建负责人**：20–200 人的团队餐，预算固定，不想被「人均超 5 块」反复打回。
- **每次聚餐负责点单的那个人**：家庭聚会、同事拼单 8–12 人，想少花时间又不想多花钱。
- **对麦当劳团餐 MCP 感兴趣的开发者**：[`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md) 是一份把 5 个团餐工具串成完整链路的可复用参考实现，含真实返回结构与踩坑记录。
