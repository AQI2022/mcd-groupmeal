# 手机点餐指南（到店自取 / 麦乐送）

> 「我在手机上点餐的时候，这东西能拿到点餐地址、门店优惠政策和菜品价格吗？」
>
> 能，而且本文的每个数字都是 2026-10-15 用真实 Token 打真服务端跑出来的。

本文只讲**个人手机点餐**这条线（到店自取 / 麦乐送）。企业团餐（20 人以上、跨门店比价、
助餐档位、拆单结论）见 [`USER-GUIDE.md`](./USER-GUIDE.md) 与 [`EXAMPLE-RUN.md`](./EXAMPLE-RUN.md)。

---

## 0. 一句话结论

| 你问的 | 能不能拿到 | 实测依据（2026-10-15，真实 Token） |
|---|---|---|
| **点餐地址** | ✅ | `delivery-query-addresses` 返回账号地址簿 **8 条**（8 城）；`delivery-create-address` 可新增 |
| **门店优惠政策** | ✅ | `query-store-coupons` 返回该店可用券（含 `couponId`/`couponCode`/适用商品/有效期）；`query-promotions` 返回团餐满折阶梯；`available-coupons` 返回麦麦省可领券 |
| **菜品价格** | ✅ | `query-meals` 返回实时菜单与单价（到店 **130** 项 / 麦乐送 **125** 项）；`calculate-price` 是**唯一权威算价口径** |
| **各店价格是否不同** | ✅（实测有差） | 西安麦乐送同一份「巨无霸+薯条」：¥51.90 / ¥51.90 / **¥52.40** |
| **能不能直接下单** | ✅（需你确认） | `create-order` 返回 `payH5Url` —— 手机点开就能付款；**本项目不会替你支付** |

## 1. 四条点餐通道与参数规则（实测确认，写错就报错）

`beType` / `orderType` / `beCode` 的传参规则是官方硬约束，**传错直接业务失败**：

| 通道 | beType | orderType | beCode | 门店从哪来 | 地址簿 |
|---|---|---|---|---|---|
| 到店自取 | 1 | 1 | **不传**（传了会报错） | `query-nearby-stores{searchType:2, city, keyword}` | **不需要** |
| 得来速 DT | 5 | 1 | **必传** | `query-nearby-stores` | 不需要 |
| 麦乐送 | 2 | 2 | **必传** | `delivery-query-stores{addressId, beType:2}` | **必须** |
| 企业团餐 | 6 | 2 | **必传** | `delivery-query-stores{addressId, beType:6}` | **必须** |

> 实测：到店自取**不需要地址簿**，只要「城市 + 位置关键词」就能列出附近门店和距离。
> 这是手机点餐里最轻的一条路（不依赖你先去 App 存地址）。

## 2. 手机上最实用的三种用法

### ① 什么都不装：在频道里说一句话（推荐）

```
手机点餐：西安长安大厦，巨无霸 + 中杯美式
```

后台跑真实链路，回你一张**点餐卡**：哪家店、用哪张券、点什么、实付多少、App 里按哪几步点。

### ② Windows 双击（给不想碰命令行的人）

| 双击 | 作用 |
|---|---|
| `bin\mcd-phone.cmd` | 依次问 城市 / 位置 / 想吃什么 / 预算 → 出点餐卡 |
| `bin\mcd-phone.cmd --demo` | 演示数据，不联网、不需要 Token，先看输出长什么样 |

### ③ 命令行 / 当库用

```bash
node src/cli.mjs phone --city 西安市 --keyword 长安大厦 --want 巨无霸,中杯美式
node src/cli.mjs phone --channel delivery --address 西安 --want 巨无霸,薯条
node src/cli.mjs phone --city 西安市 --keyword 长安大厦 --budget 30        # 不说吃什么，按预算自动配餐
node src/cli.mjs phone --city 西安市 --keyword 长安大厦 --want 巨无霸 --json
```

```js
import { solvePhoneOrder, renderPhoneCard } from 'mcd-groupmeal/phone';
const r = await solvePhoneOrder({ client, channel: 'pickup', city: '西安市', keyword: '长安大厦', want: ['巨无霸', '中杯美式'] });
console.log(renderPhoneCard(r));
```

**真要下单**（会创建真实未支付订单，返回付款 H5 链接）：

```bash
node src/cli.mjs phone --city 西安市 --keyword 长安大厦 --want 巨无霸,中杯美式 --pay
```

`--pay` 是显式确认开关：不加它，程序**只算价、不下单**。加了它也只创建订单，
**不会支付**，付款链接要你自己在手机上打开并确认金额。

## 4. 六个真坑（都是实测踩出来的，不看会得出错误结论）

### 坑 1：门店打烊时「菜单 0 项」≠「这家店没有菜单」

非营业时间调 `query-meals` 会返回 **`code=600057 门店可能已关闭或不在营业时间`**，菜单为空。
若把它当成「菜单 0 项」，会得出「这家店没有团餐/没有菜单」这种**假结论**。

本引擎的处理：识别 600057 → 把门店列进「已排除（当前非营业时间）」，而不是静默丢弃。
实测 23:38（北京时间）在西安搜到 5 家店，其中 4 家已过 23:00 打烊，只有雁塔路（营业到 23:59）出菜单。

### 坑 2：券里的商品码**可能不在菜单里**（券专属商品）

实测「新人专享-中杯美式7折」的适用商品是 `9900000119 美式中杯`，
但它在 `query-meals` 的 130 项菜单里**不存在**；不带券对它算价返回 `price=0` 且 `productList=[]`。

所以「券找货」必须**从券的 `products[]` 取商品码**，不能只在菜单里搜 ——
否则你会以为「这张券没用」，实际上它锁着一个 ¥19.00→¥13.30 的商品。

### 坑 3：比价必须校验「这份组合是否真的买齐了清单」

承接坑 2：券专属商品在「不用券」组合里会被官方**直接丢弃**，于是「不用券」反而更便宜。
若直接按价格取最小值，会算出 **「别用券更省」的假结论**（因为那份组合里少了一个商品）。

本引擎的 `priceCovers()` 会逐项校验 `calculate-price` 回执里的 `productList`，
只在「真的买齐」的组合里挑最省；买不齐的组合只作参照，并在卡片上注明「无『不用券』可比基线」。

### 坑 4：优惠券是**分渠道**的

同一家店（西安雁塔路）、同一个账号：

| 渠道 | 该店可用券 |
|---|---|
| 到店自取（orderType=1/beType=1） | **2 张**：新人专享-中杯美式7折、中杯奶铁7折 |
| 麦乐送（orderType=2/beType=2） | **0 张** |
| 团餐（beType=6） | **0 张** |

把到店券硬塞进麦乐送算价 → `code=600012 当前优惠券不可用！`

所以「我有券」和「这单能用券」是两件事，必须**按门店 + 渠道**分别查 `query-store-coupons`。

### 坑 5：麦麦省「可领取」的券，不领就用不了

`available-coupons` 返回的是**可领取清单**（实测 6 张：中薯条买一送一、王牌小食拼、
巧克力味厚松饼猪柳蛋套餐、免费脆薯饼…），**里面没有 `couponId`/`couponCode`**，
因此无法直接参与算价。必须先 `auto-bind-coupons` 一键领取，之后才会出现在
`query-store-coupons` 里并带出券 ID。

> ⚠️ `auto-bind-coupons` 会**改写你账号的券包**。本引擎默认**不代领**，
> 只在卡片上提示「还有 N 张可领」，要不要领由你决定。

### 坑 6：有些工具**只返回 Markdown，没有 JSON**

实测 `available-coupons`、`campaign-calendar` 的返回体没有 `success/code/data` 字段。
如果客户端按「非 JSON 即失败」判定，会把一次**成功**调用误判为失败
（本项目 1.0.1 修复了这个判定，并为这类工具打上 `kind:'text'` 标）。

其它两个硬约束：MCP 版本必须 ≤ 2025-06-18；限流 **600 次/分钟**，超限 429。

### 坑 7：优惠不一定来自「券」

到店自取实测：「牛肉堡单品精选 + 玫瑰红糖糍粑风味派 + 雪碧」商品小计 ¥33.50，
**没挂任何券**，`calculate-price` 仍返回 `discount=¥5.00`、实付 ¥28.50 —— 门店的**自动优惠**
（满减/随心配一类）会被官方算价直接计入。

所以卡片上的「优惠」列永远以 `calculate-price` 为准，不要用菜单价手工相加；
本引擎也只在真的挂了券时才写「用券」，自动优惠会单独注明。

## 6. 边界（如实说明）

- **不做支付**。`--pay` 只调 `create-order` 创建**未支付**订单并打印 `payH5Url`，付款必须你本人在 App/浏览器确认。
- **不代领券**。`auto-bind-coupons` 会改账号券包，默认不调。
- **不猜价格**。卡片上每个金额都来自官方 `calculate-price`；本地只用菜单价做匹配与预筛。
- **打烊就是打烊**。非营业时间门店会被明确列出并排除，不会拿「菜单 0 项」冒充「没有门店」。
- **手机端本身跑不了 Node**。要么把一句话发给工作区里的 Agent（本文 §2①），
  要么把 MCP 挂到支持 Streamable HTTP 的手机端 AI 客户端（`mcp-config.example.json` 里的
  `url` + `Authorization` 两项照抄即可，Token 等同账号身份，勿泄露）。
