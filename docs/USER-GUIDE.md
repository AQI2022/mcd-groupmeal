# 使用指南 · mcd-groupmeal 具体可以怎么用

> **一句话**：给它「**几个人 + 人均预算 + 送到哪**」，它把那个地址下**所有可配送团餐门店**全部跑一遍麦当劳官方算价，告诉你最省的那一单、以及为什么它最省。

---

## 0. 先搞清楚它管哪一段

订一次团餐的完整链路是五步：

```
① 定人数/预算 → ② 选哪家门店 → ③ 选哪个助餐档位 → ④ 选哪些商品 → ⑤ 下单支付
```

本工具负责 **②③④ 的决策**，并且把每个候选方案的金额都用官方 `calculate-price` **实际算一遍**。

它**不替你下单、不替你付钱**。`create-order` 会产生真实订单和支付链接，必须你本人在麦当劳 App / 小程序里确认付款 —— 这是刻意设计，不是没做。

### 三个最典型的使用场景

| 谁 · 什么时刻 | 你输入 | 你拿到 | 实际能省多少 |
|---|---|---|---|
| 公司行政订 20 人团建餐 | `20 / 35元 / 西安` | 同地址 3 家门店实付对比，最优带 ★ | 换一家店 **省 ¥22.20**；选错助餐档位会**多付 ¥148.00** |
| 每次聚餐负责点单的那个人 | `10 / 40元 / 长安大厦` | 满足官方搭配建议的最省商品组合 + 人均 | 不用手动凑满减，阶梯折扣自动命中最优档 |
| 想先摸底、不想花时间 | `stores --address 上海` | 各店菜单项数 / 助餐档位 / 满折阶梯 | 只用 7 次官方调用（比价要 97 次）就能看清一家店 |

## 1. 四种用法（按「你愿意花多少力气」排序）

### 用法 A · 零安装：把三件事说出来，让 AI Agent 跑 ✅ 最省事

你不需要装 Node、不需要 Token 放进文件 —— 直接对工作区里的 Agent 说：

> 帮我算一下：**20 人，人均 35，送到西安长安大厦**。

Agent 会调用本引擎并把比价结果贴回给你。这是给「我只想要结论」的人的路径。

---

### 用法 B · Windows 双击（不想碰命令行的人）

前提：本机装了 Node.js ≥ 20（<https://nodejs.org> 下 LTS 版，一路下一步）。之后：

| 双击这个文件 | 会发生什么 |
|---|---|
| `bin\mcd-meal.cmd` | 依次问你**人数 / 人均预算 / 地址**，然后出比价结果（约 30~90 秒） |
| `bin\mcd-doctor.cmd` | 自检：Token 有没有、握手通不通、工具齐不齐、地址簿几条（**出问题先跑这个**） |
| `bin\mcd-demo.cmd` | 演示模式：内置演示数据、不联网、不需要 Token，只为看清输出长什么样 |

也支持直接带参数双击不起来时在终端里写：

```bat
bin\mcd-meal.cmd 20 35 西安
bin\mcd-meal.cmd 12 45 长安大厦
```

失败时它不会只丢一个退出码，而是直接告诉你下一步该点哪里（没有 Token / 地址簿为空 / 地址文字对不上，三种原因分别给出中文指引）。

---

### 用法 C · 命令行（推荐给会敲命令的人）

```bash
# 1) 先自检（4 次官方请求，几秒钟）
node src/cli.mjs doctor

# 2) 真实比价 —— 最常用的一条
node src/cli.mjs optimize --people 20 --budget 35 --address 西安

# 3) 带上预约时间（只有 ≥4 小时提前量，专人分餐/专人摆台才会变成可选）
node src/cli.mjs optimize --people 20 --budget 35 --address 西安 --reservation "2026-10-16 12:00"

# 4) 只看门店情报（最省调用量，7 次请求）
node src/cli.mjs stores --address 上海

# 5) 要机器可读结果（给别的程序/报表用）
node src/cli.mjs optimize --people 20 --budget 35 --address 西安 --json

# 6) 完全不联网看效果
node src/cli.mjs demo
```

**全部参数**

| 参数 | 说明 | 默认 |
|---|---|---|
| `--people, -n` | 人数（`optimize` 必填） | — |
| `--budget, -b` | **人均**预算（元，`optimize` 必填） | — |
| `--address, -a` | 地址匹配文本：城市名 / 写字楼名 / 完整地址 | 取地址簿第一条 |
| `--prefer` | 偏好关键词，逗号分隔，如 `汉堡,薯条,饮料` | 无 |
| `--assist` | 只算指定助餐档位，如 `GMS001,GMS002` | 全部可用档位 |
| `--max-orders` | 拆单上限（k ≤ 3） | 3 |
| `--variants` | 每家店候选篮子数 | 3 |
| `--max-calls` | `calculate-price` 调用硬上限 | 150 |
| `--reservation` | 预约送达时间 `"yyyy-MM-dd HH:mm"` | 立即送达 |
| `--json` | 输出 JSON（含完整推理链，可复现） | 表格文本 |
| `--no-cache` | 关闭 10 分钟门店画像缓存 | 开缓存 |

> 一次 20 人比价实测约 **97 次官方算价**，约占每分钟限额（600 次）的 1/6，正常使用不会触发 429。

### 用法 D · 当成库，嵌进你自己的程序

零运行时依赖，纯 ESM：

```js
import { McpClient } from 'mcd-groupmeal/mcp';
import { optimize } from 'mcd-groupmeal';

const client = new McpClient({ token: process.env.MCD_MCP_TOKEN });
const result = await optimize({
  client,
  people: 20,
  budgetPerPersonCents: 3500,   // 单位：分
  addressQuery: '西安',
  prefer: ['汉堡'],
});

console.log(result.best.store.storeName);        // 最优门店
console.log(result.best.totals.price);           // 官方算价实付（分）
console.log(result.verdict.headline);            // 「别拆」/「可以拆」
```

也可以只复用其中一层：

```js
import { parsePromotions, bestPromotionFor } from 'mcd-groupmeal/promotions'; // 满折/满减规则判定
import { enumerateSplits } from 'mcd-groupmeal/split';                       // 拆单枚举
```

想要「把官方 MCP 挂到 AI 客户端里用自然语言点餐」，那是**另一条路**：照 [`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md) 把 `https://mcp.mcd.cn` 配进 WorkBuddy / Claude Desktop 等任意支持 Streamable HTTP 的 MCP 客户端即可。
两者分工：**官方 MCP 让你「能点餐」，本引擎让你「知道怎么点最省」。**

## 2. 前置条件（两条，缺一不可）

| # | 条件 | 怎么满足 | 不满足会怎样 |
|---|---|---|---|
| 1 | **MCP Token** | <https://open.mcd.cn/mcp> → 登录 → 控制台 → 激活 → 一键复制；然后复制 `mcp-config.example.json` 为 `mcp-config.json` 填入 Token（或设环境变量 `MCD_MCP_TOKEN`） | 直接报「没有找到 MCP Token」，并列出 3 种补齐方式 |
| 2 | **账号里至少一个收货地址** | 麦当劳 App / 小程序 → 我的 → 收货地址 → 新增保存 | `delivery-query-stores` **只接受 `addressId`**，没有地址 = **一家门店都查不到**。引擎会明确报 `EMPTY_ADDRESS_BOOK`，不会静默返回 0 家 |

> ⚠️ 第 2 条是最容易被误解成「工具坏了」的地方：**不是工具查不到，是官方接口必须由你账号里的地址来定位门店。**

## 3. 输入怎么给才不踩坑

- **`--address` 是「匹配文本」，不是「随便写个地名」。** 它在你地址簿的**已存地址**里做包含匹配：写 `西安` 会命中地址里含「西安」的那条；写 `长安大厦` 更精确。要比较 8 个城市，就得先存 8 条地址（每条约 30 秒）。
- **`--budget` 是人均，不是总预算。** 20 人 × 35 元 = 总预算 ¥700，输出里会两者都显示。
- **想用「专人分餐 / 专人摆台」必须给 `--reservation`。** 实测这两档要求提前 ≥ 4 小时且送达时间在 07:00~20:00，否则官方直接标「不可用」。
- **`--prefer` 只是偏好，不是硬约束。** 它会优先替换同类餐品，不会为了满足偏好让你超预算。

## 4. 输出怎么读

```text
┌──────────────────────────┬──────────┬──────────┬───────────┬───────────┬─────────┬────────┬──────────┐
│ 门店                     │ 助餐     │ 商品小计 │ 满折/满减 │ 配送+打包 │ 实付    │ 人均   │ 超出预算 │
├──────────────────────────┼──────────┼──────────┼───────────┼───────────┼─────────┼────────┼──────────┤
│ ★ 麦当劳西安雁塔路餐厅   │ 保鲜速达 │ ¥670.00  │ −¥209.20  │ ¥9.00     │ ¥504.80 │ ¥25.24 │ 否       │
│   麦当劳西安大话南门餐厅 │ 保鲜速达 │ ¥700.00  │ −¥217.00  │ ¥9.00     │ ¥527.00 │ ¥26.35 │ 否       │
└──────────────────────────┴──────────┴──────────┴───────────┴───────────┴─────────┴────────┴──────────┘
```

| 列 | 含义 | 怎么用 |
|---|---|---|
| 门店 | `★` 是本轮最优 | 想省钱就照着 ★ 那家下单 |
| 助餐 | 该方案用的助餐档位 | 同店换档位差价可能比换店更大 |
| 商品小计 | 打折前的商品金额 | 用来判断「离下一档还差多少」 |
| 满折/满减 | 官方优惠金额 | 全部来自官方回执，不是本地估算 |
| 配送+打包 | 配送费 + 打包费 | **不参与打折**，且 ¥510 起免配送费、¥300 仍收 ¥6 |
| 实付 | **你实际要付的钱** | 决策看这一列 |
| 人均 | 实付 ÷ 人数 | 直接和 `--budget` 对照 |
| 超出预算 | 是否超人均预算 | 「是」的方案要慎重 |

后面还有三段：

- **🏆 最优方案** —— 实付 / 人均 / 总优惠 / 比次优门店省多少 / 同店最差档位多付多少 / 折扣阶梯 / 本单商品构成。
- **🔀 拆单结论** —— 穷举 k ≤ 3 种拆法并逐单官方验价，直接给「别拆」或「可以拆」，附每种拆法贵/便宜多少钱。
- **💡 凑单提示** —— 「再增加 ¥X 即可升到 Y 折」。注意：这是**客观信息，不是建议加购**。

> `stores` 模式若某店显示「菜单 0 项」，会紧跟一行 `⚠️ 降级：query-meals 失败（…）` 说明原因（实测上海某店打烊时返回 `code=600057 门店可能已关闭或不在营业时间`）。**「0 项」是拿不到数据，不等于这家店没有团餐。**

## 5. 四个实测结论，可以直接拿去用

1. **折扣阶梯是全品牌统一的，不是逐店不同的。** 22 家门店规则签名完全一致：满 ¥300→7.8 折、¥500→7.4 折、¥1000→7 折、¥2000→6.6 折。
   → 所以「跨门店比价」的价值来自**菜单价格差异**，不是折扣差异。西安 67 个共同商品里 14 项有价差，重庆 54 项里 46 项有价差；深圳/杭州/北京/成都/武汉是 0 项。
2. **助餐档位选错是真金白银。** 同店同餐：保鲜速达 ¥504.80 / 专人分餐 ¥571.80 / 专人摆台 ¥605.30，**最大差 ¥100.50**。
3. **满折场景下拆单在数学上不可能更省。** `Σpᵢ(1−rᵢ) ≥ P(1−R)`，还要重复付配送费、并失去免配送费资格。实测拆 2 单**多付 ¥26.42~52.55**。
4. **¥510 起免配送费，¥300 还要收 ¥6。** 差一点点没到门槛时，「凑到免配送费」和「升下一档折扣」是两笔分开算的账。

## 6. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `没有找到 MCP Token` | 没有 `mcp-config.json` / Token 填错 | 跑 `bin\mcd-doctor.cmd`；按提示申请并填入 Token |
| `http=401 当前鉴权码不存在或已失效!` | Token 失效或被重置 | 回 <https://open.mcd.cn/mcp> 控制台重新复制 |
| `EMPTY_ADDRESS_BOOK` / 门店 0 家 | 账号地址簿是空的 | 麦当劳 App → 我的 → 收货地址 → 存一个 |
| `地址簿里找不到匹配「XX」的地址` | 匹配文本和已存地址文字不一致 | 打开 App 看地址原文；或改用更短的关键词（如城市名） |
| 某家店「菜单 0 项」并带 ⚠️ 降级 | 该店打烊 / 接口偶发失败，已单店降级 | 换时间段或忽略该店，整次比价不会因此崩掉 |
| 想省钱但结果都「超出预算」 | 官方分档搭配在该预算下凑不出可行组合 | 放宽 `--budget`，或加 `--prefer` 指定更省的品类 |
| `429` | 超过 600 次/分钟 | 客户端已内置令牌桶与指数退避；正常单次运行不会触发 |

## 7. 它不做什么（先说清楚，避免误解）

- **不替你下单、不替你付款。** 只算钱，付款在官方 App 完成。
- **不保证「最便宜」是绝对最优。** 候选篮子由 `--variants` 控制（默认 3/店），是「在搜索范围内的最优」，不是全商品空间的穷举最优。
- **不承诺拆单能省钱。** 能省就说能省，不能省就直接说「别拆」。
- **不代表麦当劳官方。** 本项目为麦当劳程序员节创意开发大赛参赛作品，由参赛者独立开发；餐品信息、价格与供应状态以麦当劳官方渠道实时结果为准。
