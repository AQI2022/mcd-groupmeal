# 手机安装指南 · 把「麦麦省」装到你自己的手机上用

> 目标：**在你自己的手机上，用浏览器点几下就能算出「去哪家店、点哪些、勾哪张券、实付多少」**。
> 手机上不需要装 Node.js、不需要敲命令行、不需要把麦当劳 MCP Token 交给浏览器。

---

## 0. 先选一条路（30 秒决策）

| | 路线 A｜手机浏览器 + 电脑当服务器 | 路线 B｜Android Termux 完全本地 | 路线 C｜公网隧道 |
|---|---|---|---|
| 谁在跑服务 | 电脑 / NAS | **手机自己** | 电脑（或云主机） |
| 需要电脑开着吗 | 需要 | **不需要** | 电脑要开（云主机则不用） |
| 手机需要装东西吗 | 不需要 | Termux + Node.js（约 60 MB） | 不需要 |
| 能在外面（4G/5G）用吗 | ❌ 只能同一个 Wi-Fi | ❌ 只能本机 | ✅ 任何网络 |
| 能「添加到主屏幕」 | ✅ 快捷方式 | ✅ **真正的独立 App**（localhost 是安全上下文） | ✅ 真正的独立 App（HTTPS） |
| 适合谁 | iPhone / Android，想 5 分钟搞定 | Android，想彻底脱离电脑 | 想随时随地用 |

**大多数人走路线 A。** Android 想彻底脱离电脑走路线 B。iPhone 想随时随地用走路线 C。

三张路线图先给出来：

```
路线 A  手机浏览器 ──Wi-Fi──▶ 电脑上的 node src/server.mjs ──▶ 麦当劳 MCP
路线 B  手机浏览器 ──127.0.0.1──▶ 手机上的 node src/server.mjs ──▶ 麦当劳 MCP
路线 C  手机浏览器 ──HTTPS──▶ cloudflared 隧道 ──▶ 电脑上的服务 ──▶ 麦当劳 MCP
```

## 1. 为什么必须有一个「服务端」？（这一步别跳过）

你可能会想：**「给我一个 HTML 文件，我扔手机里打开不就行了？」——不行，实测过了。**

我直接对官方 MCP 端点做了一次探测：

```
POST https://mcp.mcd.cn      （带 Origin 头，模拟浏览器跨域请求）
→ HTTP 200，响应头里 **没有 Access-Control-Allow-Origin**
```

浏览器会因为**同源策略**直接拦掉这个请求，前端代码连握手都做不到。
更关键的是：**把 Token 写进前端页面 = 把账号凭证公开给任何打开页面的人。**

所以正确架构只有一个：

```
手机浏览器  ──►  本服务（唯一持有 Token 的地方）  ──►  mcp.mcd.cn
    ▲                    │
    └── 只拿到算好的结果 ───┘
```

服务端进程内存里持有 Token，接口响应里**不含 Token**（有单测专门守这条：
`自检：响应里不含 Token`）。

## 2. 路线 A｜手机浏览器 + 电脑当服务器（推荐，5 分钟）

### 前置

- 一台电脑（Windows / macOS / Linux 都行），装好 **Node.js ≥ 20**
- 电脑上有 `mcp-config.json`（真实 Token，见 [README 第 1 步](../README.md#1-配置-mcp-token)）
- 手机和电脑连**同一个 Wi-Fi**

### 第 1 步：在电脑上起服务

**Windows 最省事**：双击 `bin\mcd-serve.cmd`（它会自动打开电脑上的浏览器给你确认界面）。

或者命令行：

```bash
node src/server.mjs
```

**不想先配 Token？** 加 `--demo` 起离线演示版，效果完全一样，只是数据是构造的：

```bash
node src/server.mjs --demo --open
```

### 第 2 步：把「手机上打开」的地址发到手机

窗口里会打印这样一段（**实测输出**）：

```
  🍟 mcd-groupmeal 手机端已启动

     电脑上打开：http://localhost:8787/?k=K7M2QP
     手机上打开：http://192.168.31.109:8787/?k=K7M2QP   ← 手机连同一个 Wi-Fi
     备用地址：  http://172.21.96.1:8787/?k=K7M2QP   (vEthernet (Default Switch))

     模式：真实 MCP（Token 来源：...\mcp-config.json）
     访问码：K7M2QP
```

把 **「手机上打开」那一整行**发给自己（微信「文件传输助手」最快），然后在手机上点开。

> `?k=K7M2QP` 是**访问码**，防止同一个 Wi-Fi 下的其他设备看到你的地址簿、甚至创建订单。
> **只需要输一次**：打开后页面会把访问码记在手机浏览器里，之后 `http://192.168.31.109:8787/` 这种短地址也能直接用。
> 访问码每次启动服务都会重新生成（除非你显式传 `--key`）。

### 第 3 步：添加到主屏幕（让它像个 App）

| 系统 | 操作 | 效果 |
|---|---|---|
| **iPhone** | 用 **Safari** 打开 → 底部「分享」→ **添加到主屏幕** | 桌面出现「麦麦省」图标，点开全屏、没有地址栏 |
| **Android** | 用 **Chrome** 打开 → 右上 **⋮** → **添加到主屏幕** | 同上 |

> iPhone 注意：**必须用 Safari**。微信内置浏览器、Chrome for iOS 里没有「添加到主屏幕」。
> 从微信里点开链接时，先点右上「…」→「在 Safari 中打开」。

### 第 4 步：开始用

底部三个标签：

- **🍔 点餐**：选渠道（到店自取 / 麦乐送）→ 填城市 + 位置（或选地址）→ 填想吃什么 → 「开始比价」
  → 出「最优门店 + 清单 + 用哪张券 + 实付」，下面还有跨门店比价、券专属加购、麦麦省可领券。
- **👥 团餐**：人数 + 人均预算 + 配送地址 → 出团餐最优方案与拆单结论。
- **⚙️ 我的**：自检（Token / 握手 / 工具 / 地址簿）、地址簿、安装说明。

真实链路一次比价要打几十次官方算价（到店比价实测 **3.9 秒 / 40+ 次调用**），
所以界面上有**实时进度日志**（SSE 推送），不会让你觉得卡死。

## 3. 路线 B｜Android Termux：手机自己就是服务器

装完之后：**不用开电脑、不用同一个 Wi-Fi**，手机浏览器打开 `http://127.0.0.1:8787/` 就能用。
而且 `localhost` 在浏览器里算**安全上下文**，所以「添加到主屏幕」得到的是**真正的独立 App**（PWA），
不是普通快捷方式。

### 步骤

1. **装 Termux**（从 **F-Droid** 装，不要用 Google Play 上那个停更的版本）：
   <https://f-droid.org/packages/com.termux/>
2. 打开 Termux，依次执行：

```bash
pkg update -y
pkg install -y git
git clone https://github.com/AQI2022/mcd-groupmeal.git
bash mcd-groupmeal/scripts/install-termux.sh
```

3. 脚本会问你 **MCP Token**（粘贴时**不显示字符是正常的**，粘完直接回车）。
   Token 从 <https://open.mcd.cn/mcp> 获取。
4. 脚本最后会跑一次自检并告诉你下一步。

### 以后每次这样用

```bash
~/mcd          # 启动服务（脚本已经帮你生成好了）
```

然后手机浏览器打开 `http://127.0.0.1:8787/`，添加到主屏幕。

**想一开 Termux 就自动起服务**：

```bash
echo '~/mcd' >> ~/.bashrc
```

**其它小技巧**：

| 需求 | 做法 |
|---|---|
| 换端口 | `MCD_PORT=9000 bash mcd-groupmeal/scripts/install-termux.sh` |
| 防后台被杀 | 脚本已内置 `termux-wake-lock`；另外去系统设置里给 Termux **关掉电池优化** |
| 从 Termux 通知栏启动 | 装 **Termux:Widget**，把 `~/mcd` 加到 `~/.shortcuts/` |
| 服务只监听 127.0.0.1 | 所以**不需要访问码**，同一 Wi-Fi 下别的设备也访问不到 |

> **iOS 没有 Termux。** iPhone 想在手机上完全本地跑，只能用 iSH 这类 x86 模拟环境装 Node，
> 又慢又折腾，**不推荐**——iPhone 用户请走路线 A 或 C。

## 4. 路线 C｜想在外面（4G/5G）也能用：公网隧道

适合 iPhone，也适合「不想每次开电脑」。

最省事的做法是 **Cloudflare 快速隧道**（免费、免注册、自带 HTTPS）：

```bash
# 1) 装 cloudflared（一个单文件程序，各平台都有）
#    https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/

# 2) 起本地服务
node src/server.mjs --port 8787

# 3) 另开一个终端，把本地端口暴露成 HTTPS 地址
cloudflared tunnel --url http://localhost:8787
```

它会打印一个 `https://xxxx-xxxx.trycloudflare.com` 的地址，手机打开这个地址即可——
**因为它是 HTTPS，所以是完整的 PWA**（可安装、可离线打开界面）。

> ⚠️ **三条必须知道的安全提醒**：
> 1. 隧道地址虽然是随机字符串，但**本质上是公开可达的**，别人拿到地址就能用你的账号下单。
>    所以务必**保留访问码**（不要加 `--no-key`），用完就 `Ctrl+C` 关掉隧道。
> 2. 不要把这个地址贴到群里、也不要长期挂着。
> 3. 快速隧道是临时的，重启后地址会变。要长期用建议自建 Cloudflare Named Tunnel
>    或把服务部到自己的服务器上，并用固定 `--key` + 反向代理加一层认证。

**另一种选择**：把整个项目部到一台云主机 / NAS / 树莓派上（`node src/server.mjs`），
手机任何时候打开都行。同样要保留访问码。

## 5. 手机连不上？按这个顺序排查

| # | 现象 | 原因与处理 |
|---|---|---|
| 1 | 手机打开是「无法访问此网站」 | **不在同一个 Wi-Fi**。确认手机连的是同一个路由器的 Wi-Fi（不是 5G 流量、也不是访客网络） |
| 2 | 同上，但确认同一个 Wi-Fi | **Windows 防火墙拦了**。会弹「是否允许 Node.js 通信」→ 勾**专用网络**并允许；没弹过就手动加规则（管理员 PowerShell）：<br>`netsh advfirewall firewall add rule name="mcd-serve" dir=in action=allow protocol=TCP localport=8787` |
| 3 | 电脑自己能开、手机打不开 | 路由器开了 **AP 隔离 / 客户端隔离**（常见于公司网、酒店网、部分光猫自带 Wi-Fi）→ 用手机热点给电脑连，或走路线 B/C |
| 4 | 打开提示「需要访问码」 | 你用的是短地址而手机还没记过码 → 用带 `?k=XXXXXX` 的完整地址打开一次 |
| 5 | 提示「访问码不正确」 | 服务重启过、码变了。回电脑窗口看新打印的码（或启动时固定：`--key MYCODE1`） |
| 6 | 电脑 IP 变了，昨天能用今天不能 | 路由器重新分配了 IP。看窗口里打印的**当前**地址；想固定可给电脑设静态 IP |
| 7 | 界面能开但比价报「没有找到 MCP Token」 | 电脑上缺 `mcp-config.json` → 双击 `bin\mcd-doctor.cmd` 确认 |
| 8 | 比价结果说「没有可比价的门店」 | **很可能真的是门店打烊**。实测 23:57 的西安：按距离前 4 家门店全部非营业，第 5 家才开着。界面会列出「已排除（当前非营业时间）」的名单 |
| 9 | 到店自取提示要填城市 | 到店链路是按「城市 + 位置关键词」搜店的，不是按你的地址簿；麦乐送才用地址簿 |

**还有个「看起来像故障其实不是」的点**：麦乐送只认地址簿里的地址（官方工具只接受 `addressId`）。
账号里一个地址都没有，就会**一家店都查不到**——这是假阴性，不是工具坏了。
先去麦当劳 App「我的 → 收货地址」存一个。

## 6. 安全与隐私：Token 到底在哪

| 问题 | 答案 |
|---|---|
| Token 存在哪？ | 只在**服务端进程内存**里（从 `mcp-config.json` 或 `MCD_MCP_TOKEN` 读入）。接口响应里不含 Token，有单测守着 |
| 浏览器能拿到 Token 吗？ | **不能**。前端只调 `/api/*`，服务端拿着 Token 去访问麦当劳 MCP |
| 访问码干什么用的？ | 防止同一个 Wi-Fi 下的其他设备读你的地址簿 / 创建订单。默认开启，`--no-key` 可关 |
| 访问码会存哪？ | 手机浏览器的 `localStorage`，只有那个 6 位码，**不是 Token** |
| `mcp-config.json` 会进仓库吗？ | **不会**。`.gitignore` 已排除，且仓库里只有 `mcp-config.example.json` |
| 会替我下单/付款吗？ | **不会自动**。默认只算钱；只有当你在结果页点「生成付款链接」并二次确认，才会创建一张**未支付**订单，付款必须你自己在麦当劳页面完成 |
| 会替我领券吗？ | **不会**。麦麦省可领券只做只读展示（领取会写入你的券包，必须由你决定） |

## 7. FAQ

**Q：手机上要不要装 Node.js？**
路线 A / C 不需要。只有路线 B（Termux 完全本地）才需要在手机上装 Node。

**Q：能不能做成微信小程序 / 原生 App？**
技术上可以，但**没必要**：这个工具的价值在「算得对」，不在 UI。用网页 + 添加到主屏幕，
零安装、零审核、改一行就能更新。真要做小程序，还得把服务端部到公网并备案。

**Q：为什么 iPhone 上「添加到主屏幕」后还是个网页样子？**
说明你是从微信/Chrome 打开的。**必须用 Safari** 打开再去「分享 → 添加到主屏幕」。

**Q：能同时给家里人用吗？**
可以，同一 Wi-Fi 下都能访问。但**地址簿和券是你账号的**，别人看到的是你的数据——
所以别把访问码给出去。

**Q：想让电脑关机后手机也能用？**
路线 B（Android Termux）或路线 C（部署到云主机/NAS）。

**Q：服务会一直开着吗？会不会占资源？**
Node 进程常驻，实测空闲时几乎不占 CPU、内存几十 MB。`Ctrl+C` 就停。
比价是**你点一次才算一次**，没有后台轮询。

## 8. 本次实测记录（可复现）

环境：Windows + Node v24.18.0 + 真实 MCP Token，`node src/server.mjs --port 8899`。

```
✅ GET /api/ping                     → {"ok":true,"demo":false,"needKey":true}
✅ 无访问码访问 /api/health          → 401（鉴权生效）
✅ 自检握手                          → {"name":"mcd-mcp","version":"1.0.0"}
✅ 工具清单                          → 35 个工具，关键 5 个全部存在
✅ 地址簿                            → 8 条
✅ 响应里不含 Token                  → 通过
✅ 到店自取（西安长安大厦，巨无霸+中杯美式）
     门店：麦当劳西安雁塔路餐厅
     清单：巨无霸×1 + 美式中杯×1
     券  ：新人专享-中杯美式7折
     商品小计 ¥45.50 → 优惠 −¥5.70 → 实付 ¥39.80
     已排除（非营业）：大话南门 / 小寨金莎 / 楷模广场 / 华旗国际
✅ 麦乐送（武汉）                    → 麦当劳武汉世贸广场餐厅｜实付 ¥35.60（配送 ¥6.00 + 打包 ¥1.10）
✅ 团餐（20 人 / 人均 ¥35）          → 麦当劳武汉世贸广场餐厅｜保鲜速达｜实付 ¥504.80｜人均 ¥25.24｜结论「别拆」
```

**同一次实测里发现并修掉的真问题**（这是「装了就能用」的关键）：

1. **打烊门店会吃掉比价名额。** `maxStores` 原本是「最多扫描几家门店」，
   而打烊门店（官方返回 `600057`、菜单为空）会占满名额。实测 23:57 的西安，
   按距离前 3 家全打烊 → 用户得到「一家都比不出来」的**错误结论**，而第 5 家雁塔路其实开着。
   已改为「**最多比价几家门店**」：按顺序往下扫，直到拿到 N 家真的算出价格的门店。
   回归测试：`phone: maxStores 是「比价几家」而不是「扫描几家」`。
2. **SSE 晚订阅会永久挂起。** 手机上刷新页面、或任务跑得比连接还快时，
   前端只收到 `snapshot` 却永远等不到 `done`，界面会一直转圈。
   已在服务端补发 `done`、前端也识别快照里的终态。
   回归测试：`端到端：手机点餐比价跑通，SSE 能拿到进度与最终结果`。
3. **自检返回结构歧义。** `/api/health` 的 `handshake` 字段原本直接返回 `serverInfo`，
   前端却按 `handshake.serverInfo.name` 读，导致「握手成功」显示不出来。已统一为 `handshake.server`。
4. **团餐「没有方案」时会崩，而不是解释原因。** 深夜门店全部非营业时，
   `optimize()` 的两个提前返回漏了 `verdict` / `splitPlans` / `savings` / `callsUsed` 四个字段，
   报告渲染读到 `verdict.headline` 直接抛 `TypeError`——用户在手机上看到的是**「比价失败」**，
   而不是「这家店现在没营业」。已把「没有可用方案」统一成一个完整的返回形状，
   并让报告渲染对残缺结果做防御式读取（这一层是用户最后看到的东西，必须给一句人话）。
   回归测试：`团餐: 没有可用方案时返回完整形状`、`团餐: 报告渲染对残缺结果也要有防御`。

**顺手修掉的一处易碎点**：前端原本「结果 → HTML」和「DOM 事件」混在一个文件里，
既没法测也没法复用。已拆出 `public/render.js` 作为纯函数渲染层，
于是界面代码第一次有了真正的测试（见下）。

**测试覆盖**：`node test/core.test.mjs`（36 项）+ `node test/frontend.test.mjs`（9 项）
+ `node test/server.test.mjs`（17 项），共 **62 项全绿**。

- **服务端测试**：访问码鉴权、**路径穿越防护**（确保 `mcp-config.json` 读不到）、
  静态资源 Content-Type、SSE 端到端、演示模式拒单、端口占用顺延，
  以及一条「**前端引用的每个 DOM id / 静态资源都真的存在**」的静态一致性检查。
- **渲染层测试**：把结果对象喂给界面代码，确认真的渲染出了门店名、券、实付金额、
  拆单结论；**门店全打烊时给的是如实说明而不是空白页**；空数据不白屏。
  样本里有一份是 2026-10-15 的真 Token 实测快照（`test/fixtures/real-phone-allclosed.json`，
  北京时间 00:0x 西安 5 家门店全部非营业——正好用来守住「无方案」这条分支）。

## 9. 一句话总结

- **iPhone 用户**：电脑上双击 `bin\mcd-serve.cmd` → 把「手机上打开」的地址发到手机 →
  用 **Safari** 打开 → 添加到主屏幕。**5 分钟搞定。**
- **Android 用户**：想省事同上；想彻底脱离电脑就装 Termux，跑一次
  `scripts/install-termux.sh`，之后 `~/mcd` 一条命令起服务。
- **要在外面用**：加一层 `cloudflared` 隧道，**保留访问码**，用完就关。

Token 永远只在你自己的机器上，浏览器拿不到；它会算钱，但**永远不会替你付款**。
